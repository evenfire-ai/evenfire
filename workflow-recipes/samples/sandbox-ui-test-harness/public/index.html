Sandbox UI · Test Harness

Each card exercises one boundary the spec sets. Click Run and compare the result with the expected behavior. Verdicts and outputs persist across in-embed navigations (e.g. #4 / #5) until you close the embed or hit Reset.

1. Reach the upstream (sanity)

A simple same-origin fetch('api/ping').

Spec: connect-src 'self' (§9.8 CSP) — fetches to the same origin are allowed.

Expected: 200 OK with JSON body.


      


      

        
2. Recipe identity headers

        

          fetch('api/whoami') echoes the request headers the upstream sees.
        

        

          Spec: §9.7 — rpc-proxy injects X-Clerum-User (cookie sub)
          and X-Clerum-Recipe (ns/name), and strips any client-supplied
          X-Clerum-* from the inbound request.
        

        

          Expected: Both headers present and correct; no client-injected
          X-Clerum-Spoof survives even if we add it.

          Even if the URL is on the SAME prefix:
          window.open('landing.html').
        

        

          Spec: §11.3 — setWindowOpenHandler ALWAYS returns
          { action: 'deny' }; http(s) URLs go to OS browser.
        

        

          Expected: OS browser opens, even though landing.html would

8. Cross-origin 302 redirect

        

          Server returns 302 Location: https://example.com/ on
          /redirect-external.
        

        

          Spec: §9.4 (Decision 5) — proxy strips off-origin Location and coerces
          status to 200. The embed never silently jumps to an external host.
        

        

          Expected: fetch sees a 200 with no Location; nothing happens
          visually.

16. Path — literal `..` traversal (browser layer)

        

          fetch('../../../etc/passwd') — relative path that tries to escape the
          recipe's view/* prefix.
        

        

          Spec: §9.4 — defense in depth. The WHATWG URL parser canonicalizes
          .. segments before the fetch leaves Chromium, so the rpc-proxy traversal
          filter (normalizeViewPath) is a backstop for forms that survive that pass —
          see #17 for the proxy-layer test.
        

        

          Expected: Any non-2xx response — the upstream's
          /etc/passwd handler must be unreachable. After browser canonicalization the
          URL becomes /api/v1/sandbox-ui/etc/passwd, which doesn't match any rpc-proxy
          route, so rpc-proxy returns 404.
        

        
        

      


      

        
17. Path — double-encoded traversal

        

          fetch('%252e%252e/secret') — double-percent-encoded ...
          Single-encoding (%2e%2e) gets pre-normalized to .. by the WHATWG
          URL parser before the request leaves the renderer, so it can't reach the proxy;
          double-encoding ships the literal %252e%252e on the wire.
        

        

          Spec: §9.4 — proxy decodes once and re-checks against the WHATWG
          double-dot path-segment forms (.., .%2e, %2e.,
          %2e%2e) so post-decode literals are also caught.
        

        
Expected: Status 400.

        
        

      


      

        
18. WebSocket upgrade

        

          new WebSocket('wss://example.com') would be CSP-blocked anyway, but try via
          same-origin new WebSocket(self+'/ws').
        

        

          Spec: §9.8 — proxy returns 426 Upgrade Required on any
          Upgrade
          header. WS isn't supported in v1.
        

        
Expected: Connection error from the WS handshake.

        
        

      


      

        
19. Download attempt

        

          <a href="..." download> click + programmatic fetch +
          URL.createObjectURL save.
        

        

          Spec: §11.2 — Electron's
          session.on('will-download', e => e.preventDefault())
          blocks every download in the partition.
        

        
Expected: No save dialog; no file ends up on disk.

        
        

      


      

        
20. Header spoof

        

          fetch('api/whoami', { headers: { 'X-Clerum-User': 'admin' }}).
        

        

          Spec: §9.7 — rpc-proxy strips every X-Clerum-* header from
          the inbound request before injecting its own.
        

        

          Expected: Server-echoed x-clerum-user
          equals the legitimate value (cookie sub), NOT
          "admin". X-Clerum-Spoof entirely absent.
