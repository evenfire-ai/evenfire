User Approval Requests v0.1 — Architecture

Step-level gating in coordinator Pod, LLM-isolated tokens, dedicated gateway :8092

Approval Request Flow (A)

  • 1. Coordinator detects step.requiresApproval
  • 2. POST /workflow-approvals/request via gateway :8092
  • 3. control-api validates JWT + allowlist + persists
  • 4. Emits event to notification_deliveries
  • 5. Coordinator polls GET /:id/status every 5s

User Decision Flow (B)

  • 1. User → external-rest-api (session/OAuth)
  • 2. external-rest-api → control-api decision route
  • 3. control-api validates user eligibility
  • 4. Updates status: pending → approved/denied
  • 5. Coordinator observes polling result → resumes step

Token Auth Chain

  • WRC/HCC → control-api: InternalControl JWT with issuer-specific HS256 secret
  • control-api → mcp-host runtime: mcpHostJwt access, refresh, and control tokens
  • hostRefs bind each token to namespace/name
  • Refresh token rotated one-time on every use
  • mcp-host pods never mount InternalControl JWT
